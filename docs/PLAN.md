작성일: 2026-11-07. 기준 문서: Notion "게임 개발(w/문성준, 김지훈)" 페이지와 GAME 2 태스크 DB.

이 문서는 "무엇을 왜 만드는가"를 담는다. 진행 상황과 다음 할 일은 [WORKLOG.md](WORKLOG.md)에 있다.

- 핵심 경험: 가챠의 희열과 절망. 랜덤 자체가 세계관이다. [Notion]

- 코어 루프: 전투 → 클리어 → 보상 → 강화 → 전투. [Notion]
- 제외 확정: 턴제, 경로 커스터마이징, 아이템, 이자, 리롤, 유닛 경험치. [Notion]

## 3. 게임 설계

### 한 판 흐름

타이틀 → 난이도·테마 선택 → 준비 시간에 뽑기/배치/조합/강화 → 웨이브 → 전 웨이브 클리어 시 Clear, 라이프 0이면 Gameover.

### 시스템

| 시스템 | 내용 |
|---|---|
| 웨이브 | Easy 30 / Normal 40 / Hard 50 / Extreme 60, 웨이브당 약 1분, 10웨이브마다 보스 [제안]. Hard부터 경로 분기 [Notion] |
| 적 | Nautolan → Klaed → Nairan 세력 전환, 3세력 × 함선 8종 [제안] |
| 라이프 | 적이 경로 끝에 도달하면 감소, 0이면 Gameover [Notion] |
| 재화 | 적 처치 + 웨이브 클리어 보상 [Notion]. 이자 없음 [Notion] |
| 뽑기 | 우측 하단 버튼, 화면 중앙 부근 생성 [Notion]. 골드 소모, C 80 / B 15 / A 4.5 / S 0.5% [제안] |
| 배치 | 격자 1칸 1유닛, 겹치면 원위치, 경로 칸 금지, 드래그 중 격자 표시 [Notion] |
| 조합 | 조합대 없이 드래그로 합침 [Notion]. 같은 ID 2개 + 골드(C 10, B 40, A 160) → 상위 등급 랜덤 1개, 1성 [제안] |
| 강화 | 1~3성 [Notion]. 유닛 클릭 후 하단 버튼. 성공 70%, 40%, 실패 시 골드만 소모 [제안] |
| 공격 타입 | SHOT = 투사체, ZONE = 경로 위 지속 장판 [Notion: 테란 드라이 → ZONE, 앳모스피어 → SHOT] |
| 증강 | 3택 카드 패널, 공속·공격력·범위, 패널 표시 중 게임 정지 [Notion] |
| 시너지 ZONE | 증강 선택 시 격자에 버프 구역 지정, 구역 안 유닛 강화 [Notion]. 크기·중첩 규칙 [제안] |
| 필살기 | 쿨타임 전역 스킬, 일정 라운드마다 교체 선택 [Notion, 검토 상태] |
| 편의 | 배속, HUD, 확률표 [Notion] |

### 유닛 표

| 등급 | 종류 | 행성 타입 [Notion] | 이펙트 [Notion] |
|---|---|---|---|
| C | 12 | 테란 드라이(FR=ZONE), 노 앳모스피어(FS=SHOT) | 유닛 폴더에 있음 |
| B | 5 | 구름 계열(가스 자이언트, 테란 웻, 아이슬란드) | 재활용 |
| A | 6 | 스타, 라바, 토성 | Magic Shot 4 |
| S | 6 | 갤럭시, 블랙홀 | Magic Shot 3 / Portal |

ID 규칙: `PRD-등급-타입-번호` (예: `PRD-C-FR-01`). 공식 명칭은 ID, 별칭은 부가 정보 [Notion].

## 4. 기술 구조

2026-02-21 팀 결정(데이터 주도 설계, Resource 기반)을 따른다.

```
data/units/*.tres            UnitData: 유닛 1종 = tres 1개
data/enemies/*.tres          EnemyData
entities/units/unit.tscn     유닛 공용 씬 (UnitBase)
entities/enemies/enemy.tscn  적 공용 씬 (EnemyBase)
entities/projectiles/        투사체, ZONE 장판
global/                      GameSetting(선택값), GameState(런타임 상태), Catalog(데이터 로더)
scenes/game/                 game_play, grid, wave_manager, hud, maps(경로만)
tests/                       헤드리스 테스트
```

원칙:
- 드래그와 입력은 `GridManager`만 담당한다. 유닛 스크립트에 입력 코드를 두지 않는다 (UNIT-005 원인).
- 유닛·적 추가는 tres 추가만으로 끝나야 한다 (COMMON-006 "행성 추가 용이성").
- 폴더 스캔은 export의 `.remap`을 처리한다.
- 맵 씬은 경로만 가진다. 웨이브는 `WaveManager`가 데이터로 진행한다.

## 6. 검증 방법

- 로직: `tests/` 헤드리스 테스트 ([WORKLOG.md](WORKLOG.md)의 명령 참고).
- 화면: 실제 창으로 실행해 스크린샷 확인.
- 재미와 손맛: 사용자 플레이로만 판단한다. Claude는 판단할 수 없다.

## 7. 알려진 위험

- `.gitignore`에 `*.import`가 있어 PC마다 텍스처 UID가 달라진다 (`title_screen.tscn`의 UID 변경이 이 때문). 경로로 복구되어 동작에는 문제없다.
- 에셋 라이선스(Foozle 함선, 이펙트 팩, DNF 폰트, deep-fold)는 Steam 전 확인 필요.
- 증강 레퍼런스 이미지는 상용 게임 화면이므로 카드 구조만 참고한다.
- GroMoon 로컬 작업이 나중에 푸시되면 `grid.gd`, 유닛 스크립트에서 충돌한다. 이쪽 재구현을 기준으로 정리한다.
